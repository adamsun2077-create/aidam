# 按需连接自己的服务

Starter 不包含任何可直接使用的第三方登录状态、令牌、服务器地址或企业配置。所有连接默认关闭，使用者按服务官方流程自行登录并授予权限。

## 推荐顺序

先跑本地任务，再接一个文档服务；确实需要数据分析或企业协作时，再接对应平台。每接一个服务，做一次最小的只读验证。

| 连接类型 | 可能的用途 | 需要自己准备 |
|---|---|---|
| 飞书或其他文档平台 | 文档推拉和客户方案 | 账号、官方工具、目标文档权限 |
| Confluence 或公司知识库 | 公司知识检索 | 公司授权、服务地址、官方支持的访问方式 |
| 数据平台的 MCP / API | 分析、报表和演示 | 自己的租户、空间、项目权限 |
| 企业微信等协作系统 | 经授权的工作消息检索 | 企业批准的集成与权限 |
| 私有服务器 | 部署自己的服务 | 自己的主机、部署用户、SSH 配置 |
| 云端交接 | 异地起草与本地合并 | 私有存储、人工选定的最小上下文 |

这些是接入位置和用途示例，不是已经实现或验证的连接。具体产品是否支持某项操作，以使用时的官方文档及实际授权为准。

## 每个桥只记录非敏感说明

用 `operations/docs/templates/bridge.md` 在 `system/bridges/服务名/README.md` 建说明。只记录用途、状态、凭据引用名、验证方法、权威来源与同步规则。令牌、Cookie 和密码放工作区外的凭据存储，不写入说明。

可以在自己的 `system/local.json` 中手动登记非敏感状态：

```json
{
  "owner": "我的称呼",
  "bridges": {
    "document-service": {
      "enabled": false,
      "credential_env": "DOCUMENT_SERVICE_API_KEY"
    }
  }
}
```

这里只引用环境变量名。Starter 不会自动读取该变量、连接服务或改变权限。

## 连通后怎样验收

1. 读取一个自己有权访问的测试资源；确认账号、空间和目标正确。
2. 如确需写入，先列明目标、变更内容和影响，取得明确授权。
3. 写入后回读验证，记录资源类型、资源标识和更新时间。文档与目录分开管理。
4. 连接断开或权限不足时如实报告；不绕过登录、不模拟其他人的身份。

某条连接若只向特定工具开放，明确记录“专属连接”。其他工具通过已授权的文件交接使用结果，不从旁路抓取消息。

## 云端交接默认不启用

需要时可人工创建 `cloud/inbox/` 和 `cloud/outbox/`，使用交接模板。仅放为当前任务选定并复核的资料；默认不发送 MEMORY 全文、客户原件或会话历史。云端草稿合并到本地正式位置并验证后，才算落地。

Starter 不附带云同步脚本、后台任务或远程仓库配置。接入前先确定双方权限、同步范围、冲突留存和撤销方式。
